# 图库输入源全模式对等（v7）—— 产品方案（讨论稿）

> 状态：方案评审，未实施
> 前置事实：v6 已实现收敛模式（强单主题/成套）的图库输入：单文件夹 + 1-3 张核心参考图 → 跳过 2.4s → 2.4.5 看图出 blueprint。多主题模式仍只能吃趋势报告（后端 400 拦截）。

---

## 1. 需求与差距

用户诉求：工作台第一步的输入改造为两种**并行**选择——(a) 趋势报告路径（现状）；(b) 印花图案库里的多张图片。

与 v6 现状的差距有两点：

| # | 差距 | 说明 |
|---|---|---|
| 1 | **多主题模式不支持图库** | 目前图库只服务收敛模式；用户要的是"第一步"层面的对等选择，即三种设计模式都能用图库替代趋势报告 |
| 2 | **只能取单文件夹** | v6 限制一次只能选一个方向文件夹内的 1-3 张；"图案库里面的多张图片"隐含跨文件夹自由多选 |

## 2. 核心抽象：从「选文件夹」升级为「组参考图集」

图库的两级结构（母主题 × 方向文件夹，方向即当初从趋势报告页裁剪归类的产物）天然携带主题语义。v7 把用户的选择结果定义为一个**参考图集（Reference Set）**：

```
ReferenceSet = [
  { 方向: "植物脉络方向", 来源母主题: "山系户外童装花型TOP热榜", 图: [a.png, b.png] },
  { 方向: "贴布徽标方向", 来源母主题: "山系户外童装花型TOP热榜", 图: [c.png] },
  ...
]
```

**用户跨文件夹勾图，系统按来源文件夹自动分组成"方向"**——一个方向组 ≈ 趋势报告里的一个子主题。这样图库输入和趋势报告输入在概念层完全同构，三种模式的语义映射水到渠成：

| 设计模式 | 趋势报告路径（现状） | 图库路径（v7） |
|---|---|---|
| 🎨 多主题 | 2.4 从报告选 2-3 个子主题 + 色号映射 | 用户选图自带分组：**每个来源文件夹 = 一个主题方向**；校验 2-3 个方向、每方向 1-3 张。新节点 **2.4p 方向映射**只做 2.4 的后半职责（色号→方向映射 + 整波策略），"选主题"由用户亲手完成 |
| 🧬 强单主题 | 2.4s 选 1 个主题 | v6 现状（1 个方向 + 1-3 张）保持不变 |
| 👕👖 成套 | 同上 | 同上 |

一个值得注意的产品判断：**图库路径下多主题模式的"选主题"环节从 LLM 决策变成了用户决策**——用户勾哪些文件夹的图，主题就定了。这符合图库输入的初衷（用户已经人工裁剪归类过，比 LLM 从文字重新选更准），还省掉一次 2.4 的 LLM 调用（~33k token）。

## 3. 管线改造（仅多主题 × 图库 组合需要新东西）

```
图库 × 多主题:
  2.1 → 2.2 → 2.3 → 2.4p 方向映射★ → 2.5(带参考图)★ → 2.6/7/8
```

**2.4p 方向映射（新节点，prompt 04p）**：输入 = 方向分组清单 + 每方向参考图（附图）+ 款式分析 + 色号识别 + 性别规划；输出 = 与 2.4 完全同 schema（选用主题列表 = 用户的方向组、色号到主题映射、整波策略）。硬约束：不得增删方向，只做映射和策略描述。输出同构 ⇒ 下游 2.5/历史避重/final JSON 零改动兼容。

**2.5 带参考图设计（增强）**：图库路径下，每个色号设计时在现有 2 张图（款图+色号图）之外，追加其分配方向的 1-3 张参考图，prompt 中声明"优先从参考图抽象图案元素与构图语言，禁止照抄整图"。这是图库输入的价值核心——视觉锚定直达单色设计。1536 压缩下每张参考图约 +1.5-2k token。

**主题名与历史避重**：方向组的主题名 = 文件夹名（如"植物脉络方向"），子主题编号用 `PL-<文件夹名hash4>` 格式。历史避重照常按名字记账——同一文件夹反复使用会被避重提示约束（跨输入源也生效，合理）。

## 4. 交互设计（工作台第一步）

1. **「输入源」Segmented 提升为全模式可见**（现在只在收敛模式显示）：📄 趋势报告 / 🖼 印花图案库。选图库时趋势报告下拉隐藏（互斥、并行、对等）。
2. **选图 Modal 升级为跨文件夹多选**：保留现有两级浏览（文件夹网格 → 图片网格），增加"已选购物车"条——顶部常驻显示 `已选 N 张 · M 个方向` 的分组 chips，可点 × 移除；文件夹间自由进出，勾选跨文件夹累积。
3. **按模式动态校验**（Modal 确认按钮旁实时提示）：多主题 = 2-3 个方向、每方向 1-3 张；强单主题/成套 = 1 个方向、1-3 张（v6 规则不变）。
4. **选完的回显**：InputsPanel 显示方向分组摘要（方向名 + 缩略图条 + 各方向张数），替代趋势报告下拉的位置。
5. **夹具兼容**：ReferenceSet 存入 fixture（文件夹名 + 文件名列表），应用夹具完整恢复。

## 5. 成本影响（按现行单价口径估算）

| 项 | 变化 |
|---|---|
| 2.4 → 2.4p | 省 LLM 选主题的思考，但要带全部选图（6-9 张 ×~1.8k）≈ 打平或略省 |
| 2.5 每色号 | +1-3 张参考图 ≈ **+2-6k token in/色**；9 色 run 约 +20-50k |
| 整体 | 多主题 run 约 +5-10% 输入 token，换视觉锚定的确定性——值得 |

## 6. 分期

**P0（本期）**：多主题支持图库（2.4p 节点 + prompt 04p；Modal 跨文件夹多选 + 分组校验；2.5 带参考图；backend ReferenceSet 装配 + fixture 存取；解除 Mode A 400 拦截）。

**P1**：收敛模式放宽跨文件夹（引入"主方向 + 辅助参考图"概念，blueprint 仍收敛单主题但可参考异方向图做变体维度启发）。

**P2**：图库管理闭环——页面内增删图/重命名方向；把生图结果一键"回流入库"沉淀为新参考图（设计资产飞轮）。

## 7. 待拍板 → 已拍板（2026-07-13）

1. **2.5 不带参考图** ✅：参考图只作用于主题层。2.4p 必须输出**丰富的「图案视觉描述」**（每方向一段，类似 blueprint 英文描述的简化版）作为视觉信息的文字化载体，填入 2.5 的"分配主题完整描述"。2.5 节点零改动。
2. **方向数/图数不设限** ✅：不做数量校验，UI 仅显示计数（收敛模式的 3 张上限一并解除；收敛仍限单文件夹，跨文件夹归 P1）。
3. **方向命名 = 文件夹名** ✅：子主题编号 `PL-<hash4>`，名称原样用文件夹名，历史避重可对账。
