# Fitting Room 升级：波段上新管理 — 产品方案 PRD

> 2026-07-17 拍板版。Fitting Room 从"拍摄组合工作台"升级为"上新排期资产库"：look 是资产，波段（Wave）是排期容器。

## 1. 已拍板决策

| # | 问题 | 决策 |
|---|------|------|
| 1 | look 归属模型 | **至多一个波段**。新 look（含生图完成自动同步）默认进「未分波段」池；移组 = 从原波段移到新波段 |
| 2 | 波段「款式数」口径 | **波段内去重**：同一张款色图在多个 look 里复用只计 1 款；与 look 数并排展示 |
| 3 | 波段状态 | **手动状态**：规划中（默认）/ 已上架，用户手动切换 |
| 4 | 公网访客权限 | **只读**：guest 可看波段分组与元信息；创建/编辑/归组/改状态仅 admin |

## 2. 数据模型

新表 `waves`：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | `wv-` + 时间戳 + 随机 |
| name | TEXT | 波段名（自由文本，如「8月第1波」） |
| planned_launch_date | TEXT | 预备上架时间（日期，可空） |
| status | TEXT | `规划中` / `已上架`，默认规划中 |
| created_at / updated_at | TEXT | 创建 / 更新时间；成员变动也刷新 updated_at |

`looks` 表加列 `wave_id TEXT`（可空，空 = 未分波段）。ALTER TABLE 增量迁移，与现有迁移风格一致。

派生统计（查询时算，不落库）：
- **look 数**：`COUNT(looks WHERE wave_id = ?)`
- **款式数**：波段内所有 look 的上/下装款色图文件名去重后计数（上下装齐 = 2 款来源，复用去重）

## 3. API

- `GET /waves` — 列表（含每波段派生统计），排序：预备上架时间升序，无日期垫底
- `POST /waves` — 创建（name 必填；可同时带 look_ids 初始归组）
- `PATCH /waves/{id}` — 改名 / 改上架时间 / 改状态
- `DELETE /waves/{id}` — 删除波段，成员 look 的 wave_id 置空回未分波段池（**不删 look**）
- `POST /waves/{id}/looks` — 批量加入（look 已在其他波段则自动移过来）
- `POST /waves/unassign` — 批量移出回未分波段
- 导出：现有 looks 导出接口加 `wave_id` 过滤参数，波段头一键"导出本波段"

公网中间件：`GET /waves` 加入 guest 读白名单；所有 waves 写操作不进白名单（自然只读）。

## 4. 前端（FittingRoomPage）

**视图切换**（Segmented）：
- **平铺视图**：现状不动（排序 / 文本编辑 / 导出照旧），look 卡加波段角标，顶部加波段筛选下拉
- **波段视图**：参考视觉模板库分组卡片——每波段一个可折叠区块，按预备上架时间排序；「未分波段」置顶。区块头 = 元信息条：`波段名 · 状态标签 · 预备上架 MM-DD · X 款 · Y look · 创建/更新时间` + 操作（行内改名 / 日期选择 / 状态切换 / 导出本波段 / 删除波段）

**归组交互**（复用组套模式的多选交互）：
- 进入「波段管理」多选态 → 勾选 look → 底部操作条：「创建新波段」/「加入已有波段 ▾」/「移出波段」
- v1 不做拖拽

**访客**：guest 隐藏全部波段写操作入口（沿用现有 guest 探测），仅保留视图切换与查看。

## 5. 边界与约定

- 删除 look：从波段统计中自然消失，不阻断
- 波段重名：允许（用 id 区分），不做唯一约束
- 状态与日期解耦：日期只是展示信息，不自动驱动状态（决策 #3 手动）
- CSV 导出格式不变，仅增加按波段过滤的入口
